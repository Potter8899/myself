# POTTER PERSONAL SPACE — เวอร์ชันเว็บล้วน

เว็บแสดงตัวตนสำหรับให้คนดูเท่านั้น: **ไม่มี** Backend, ฐานข้อมูล, แอดมิน, ระบบสมาชิก/ล็อกอิน, แชต, สมุดเยี่ยม, ฟอร์มติดต่อ และ Discord Bot
เป็นไฟล์ HTML/CSS/JS ล้วน เปิดจากโฮสต์สแตติกที่ไหนก็ได้ ไม่ต้องมี API key หรือรหัสลับใดๆ (ไม่มีการส่งข้อมูลออกจากเว็บ ยกเว้นโหลดฟอนต์จาก Google Fonts)

## ✨ เพิ่มรูป / ไฟล์ แบบง่าย (แก้ที่ `js/media.js` ไฟล์เดียว)
ไม่ต้องแตะ `content.js` เลย ทำ 3 ขั้น: **วางไฟล์ในโฟลเดอร์ → เพิ่มชื่อใน `js/media.js` → อัปโหลดขึ้น GitHub ใหม่**

| อยากเพิ่ม | วางไฟล์ที่ | เพิ่มใน `js/media.js` |
|---|---|---|
| รูปโปรไฟล์ (รูปใหญ่หน้าแรก) | `img/profile.jpg` | `profilePhoto: "img/profile.jpg",` |
| รูปแกลเลอรี | `img/gallery/` | `"img/gallery/a.jpg",` หรือ `{ src: "img/gallery/b.jpg", caption: "ห้องของผม" },` ในช่อง `gallery` |
| ไฟล์ให้คนโหลด (zip, pdf, jar) | `files/` | `{ name: "ม็อดของผม v1", file: "files/my-mod-v1.zip", note: "สำหรับ 1.20.1" },` ในช่อง `files` |

ตัวอย่าง:
```js
gallery: [
  "img/gallery/a.jpg",
  { src: "img/gallery/b.jpg", caption: "ห้องของผม", category: "workspace" },
],
files: [
  { name: "ม็อดของผม v1", file: "files/my-mod-v1.zip", note: "สำหรับ Minecraft 1.20.1" },
],
```
**กฎสำคัญ**
- ตั้งชื่อไฟล์เป็นภาษาอังกฤษ/ตัวเลข **ไม่มีเว้นวรรค** เช่น `my-room.jpg` (ชื่อไทยหรือมีช่องว่างจะไม่แสดง)
- ทุกบรรทัด (ยกเว้นบรรทัดสุดท้ายก็ได้) ต้องลงท้ายด้วยเครื่องหมาย `,`
- รูปแกลเลอรีและไฟล์ดาวน์โหลดจะแสดงในแท็บ **Gallery** · รูปแนะนำให้เป็น .jpg/.webp ไม่ใหญ่เกิน ~1 MB
- ไฟล์ใหญ่มาก (เกิน ~25 MB) ควรใช้ลิงก์ `https://` (เช่น GitHub Releases) แทนการวางในโฟลเดอร์

## 🧑 แก้ชื่อ / ชั้น / ชื่อเล่น
อยู่ที่ `js/content.js` ในส่วน `profile` (`fullName`, `grade`, `nickname`) — แสดงเป็นการ์ดใต้ชื่อ POTTER ในหน้าแรก และอยู่ในข้อความ "ผมคือใคร" ของแท็บเกี่ยวกับ · ช่อง `en` เว้นว่างได้ จะใช้ภาษาไทยแทน · ถ้าไม่อยากแสดงข้อมูลไหน ให้ลบบรรทัดนั้นหรือเว้นว่าง `""`

## 🗂️ แท็บ
เมนูด้านบน (หน้าแรก / เกี่ยวกับ / ทักษะ / ผลงาน / แกลเลอรี / บล็อก / ติดต่อ) เปิดทีละแท็บ ไม่เลื่อนต่อกันยาวแล้ว · ลิงก์ตรง เช่น `https://เว็บของคุณ/#gallery` · ปุ่ม Back ของเบราว์เซอร์ย้อนกลับแท็บได้

## แก้เนื้อหา
แก้ไฟล์เดียวคือ **`js/content.js`** (มีคอมเมนต์อธิบายทุกช่อง): ชื่อ/แนะนำตัว/เกี่ยวกับ, ทักษะ, ไทม์ไลน์, โปรเจกต์, แกลเลอรี, บล็อก (Markdown), ลิงก์โซเชียล/อีเมล · ข้อความสองภาษาเขียนเป็น `{ th: "...", en: "..." }` ช่องที่เว้นว่างจะถูกซ่อน
- **รูปโปรไฟล์**: วางรูปจริงของคุณเป็น `img/profile.jpg` (ไม่มีรูป → แสดงตัวอักษร P และไม่เปิด lightbox) ผมไม่ได้สร้างรูปบุคคลให้
- รูปอื่น: วางใน `img/` แล้วใส่ path (เช่น `img/gallery/desk.jpg`) หรือลิงก์ `https://` · แนะนำไฟล์ WebP/JPG ขนาดไม่ใหญ่เกินไป
- ลิงก์ภายนอกรับเฉพาะ `https://` (อย่างอื่นจะไม่ถูกแสดง) · บล็อกที่ตั้ง `status: "draft"` จะไม่แสดง
- ข้อมูลเริ่มต้นมีเฉพาะที่ได้มาจากโปรเจกต์เดิมและรายการที่คุณระบุ ไม่มีประวัติ/ความสำเร็จ/เปอร์เซ็นต์ทักษะที่แต่งขึ้น

## เผยแพร่ด้วย GitHub Pages (ตั้งไว้ให้แล้ว: `.github/workflows/pages.yml`)
1. สร้าง repository บน GitHub แล้ว push โฟลเดอร์นี้ทั้งหมดขึ้นไปที่ branch `main` (ต้องเป็น **public** ถ้าใช้บัญชี GitHub Free — ตามเอกสาร GitHub Pages)
2. ไปที่ **Settings → Pages → Build and deployment → Source** เลือก **GitHub Actions** (ทำครั้งเดียว)
3. ทุกครั้งที่ push เข้า `main` (หรือกด **Actions → Run workflow**) ระบบจะ: ตรวจไวยากรณ์ JS → รันเทสต์ Markdown และเทสต์เบราว์เซอร์ → ถ้าผ่านหมดจึง deploy (ถ้าเทสต์ล้ม **จะไม่ deploy** เว็บเดิมยังอยู่) · Pull Request จะรันเทสต์อย่างเดียว ไม่ deploy
4. URL เว็บจะแสดงในหน้า Actions ของรอบนั้น (ปกติ `https://ชื่อผู้ใช้.github.io/ชื่อrepo/` หรือถ้าตั้งชื่อ repo เป็น `ชื่อผู้ใช้.github.io` จะได้ `https://ชื่อผู้ใช้.github.io/`)
- workflow ใส่ canonical URL / Open Graph / sitemap ให้อัตโนมัติจาก URL จริง (ไม่ต้องรัน `set-site-url.sh` เอง) และเผยแพร่เฉพาะไฟล์ที่ผู้เข้าชมต้องใช้ (ไม่รวม tests/ และ .github/)
- ทุก path ในเว็บเป็นแบบสัมพัทธ์ จึงใช้ได้ทั้งที่ราก (`/`) และใต้ชื่อ repo (`/ชื่อrepo/`) · ใช้โดเมนของตัวเองได้ผ่าน Settings → Pages → Custom domain
- `img/profile.jpg` เป็นไฟล์เสริม: ยังไม่ใส่ก็ deploy ได้ (จะแสดงตัวอักษร P) · `.github/dependabot.yml` จะเปิด PR เตือนเมื่อ action ที่ใช้มีเวอร์ชันใหม่ (workflow ปักไว้ที่ checkout@v4, configure-pages@v5, upload-pages-artifact@v3, deploy-pages@v4)
- **หมายเหตุ**: `robots.txt` ใต้ชื่อ repo (`/repo/robots.txt`) เสิร์ชเอนจินไม่อ่าน (ต้องอยู่ที่รากโดเมน) แต่ไม่ทำให้เว็บใช้งานไม่ได้ · ถ้า deploy ไม่ขึ้น ให้ดูใน Actions ว่าล้มที่ขั้นไหน และตรวจว่าเลือก Source = GitHub Actions แล้ว

## เผยแพร่ที่อื่น
อัปโหลดทั้งโฟลเดอร์ไปโฮสต์สแตติกใดก็ได้ (Render Static Site: ไม่มี build command, publish directory = `.`, Cloudflare Pages ฯลฯ) แล้วรัน `sh set-site-url.sh https://โดเมนของคุณ` หนึ่งครั้งเพื่อตั้ง canonical/sitemap — ตรวจเงื่อนไขแผนฟรีล่าสุดกับผู้ให้บริการเอง

## มีอะไร
Hero + การ์ดโปรไฟล์ 3D (เบลอ/มืด → ชัด/แสงขาว/tilt/ขอบนีออนตอน hover, รีเซ็ตเมื่อเมาส์ออก, คลิกเปิดรูปเต็มจอ ซูมได้, ESC/คลิกนอก/ปุ่มปิด, รองรับสัมผัส), พื้นหลังอวกาศ (ดาว, nebula, ดาวตก, parallax), About + Timeline, Skills (กรองหมวด, คลิกเพื่อค้นโปรเจกต์ที่เกี่ยวข้อง), Projects (ค้นหา/กรอง/Featured/รายละเอียด/รูปประกอบ), Gallery (masonry, lazy, lightbox), Blog (ค้นหา/หมวด/แบ่งหน้า/เวลาอ่าน), ไทย/อังกฤษ, รองรับมือถือ, ลดการเคลื่อนไหว (reduced motion)
ลิงก์รายละเอียดโปรเจกต์/บทความใช้ hash (`#/project/slug`, `#/blog/slug`) แชร์ได้ แต่เสิร์ชเอนจินไม่ index แยกรายหน้า
